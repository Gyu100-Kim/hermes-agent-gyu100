## 1. 프로그램과 소스코드

**프로그램**은 컴퓨터에게 시키는 일의 목록이고, **소스코드**는 그 목록을 사람이
읽고 쓸 수 있는 글자로 적어 놓은 것입니다. 요리에 비유하면 소스코드는 **레시피**,
프로그램 실행은 그 레시피대로 **요리를 하는 것**입니다.

Hermes 저장소는 이런 레시피 파일 수백 개가 폴더별로 정리된 큰 요리책입니다.
예를 들어 `run_agent.py`라는 파일은 "AI 에이전트를 어떻게 움직일지"에 대한
레시피입니다. 우리가 이 학습자료에서 하는 일은 이 요리책을 **목차부터 개별
레시피의 한 줄 한 줄까지** 읽어 내려가는 것입니다.

## 2. 파이썬, 모듈, 패키지

**파이썬(Python)** 은 사람이 읽기 쉬운 문법을 가진 프로그래밍 언어입니다. Hermes의
거의 모든 코드가 파이썬으로 되어 있습니다(파일 확장자 `.py`).

- **모듈(module)** = 파이썬 파일 하나. 예: `hermes_state.py`.
- **패키지(package)** = 모듈을 모아 놓은 폴더. 예: `agent/`, `tools/`, `gateway/`.
- **import** = 다른 모듈의 기능을 빌려 쓰는 문장. 레시피에서 "소스는 32쪽의
  기본 소스를 사용"이라고 참조하는 것과 같습니다.

폴더 구조만 봐도 "이 프로그램이 어떤 부품들로 이루어졌는지"를 알 수 있기 때문에,
[01_source_overview.md](01_source_overview.md)에서 디렉토리 지도를 가장 먼저 봅니다.

## 3. 서버와 클라이언트, API

- **서버(server)** = 요청을 받아 처리해 주는 컴퓨터. 식당의 **주방**.
- **클라이언트(client)** = 요청을 보내는 쪽. 식당의 **손님**.
- **API** = 요청을 보내는 규칙(메뉴판 + 주문 방법). "이 주소로, 이런 형식으로
  주문하면, 이런 형식으로 응답한다"는 약속입니다.

Hermes는 LLM 회사(OpenAI, Anthropic 등)의 서버에 **API로 질문을 보내고 답을 받는
클라이언트**입니다. "모델을 호출한다(call)"는 말은 곧 "LLM 서버에 API 요청을 한 번
보낸다"는 뜻입니다. 호출은 건당 돈이 들기 때문에, 뒤에서 배울
프롬프트 캐싱 ([용어사전](../dict/01_llm_basics.md#prompt-caching))·반복 예산 같은
장치들이 중요해집니다.

## 4. JSON — 컴퓨터들이 쓰는 공용 메모지

**JSON**은 데이터를 `{"이름": "값"}` 모양의 글자로 적는 형식입니다. 사람도 읽을 수
있고 어떤 프로그래밍 언어도 읽을 수 있어서, 서로 다른 프로그램이 데이터를 주고받을
때 공용 메모지처럼 씁니다.

```json
{"name": "terminal", "arguments": {"command": "ls -al"}}
```

위 JSON은 "terminal이라는 도구를 `ls -al`이라는 명령으로 실행해 달라"는 뜻입니다.
LLM이 도구를 쓰고 싶을 때 정확히 이런 모양의 JSON을 만들어 보냅니다
(→ [tech_background/01_tool_calling.md](tech_background/01_tool_calling.md)).

## 5. LLM — 다음 낱말 맞히기의 달인

**LLM(대규모 언어 모델, Large Language Model)** ([용어사전](../dict/01_llm_basics.md#llm))은
"지금까지의 글 다음에 올 가장 그럴듯한 낱말"을 맞히도록 엄청난 양의 글로 훈련된
프로그램입니다. 이 단순한 능력을 반복하면 문장이 되고, 대답이 되고, 코드가 됩니다.

중요한 특징 두 가지:
1. LLM은 **기억이 없습니다.** 매번 대화 전체를 처음부터 다시 읽고 다음 말을
   만듭니다. 그래서 "대화 기록을 어떻게 관리하느냐"가 에이전트 설계의 핵심이 됩니다.
2. LLM은 **글자만 다룹니다.** 파일을 열거나 인터넷 검색을 스스로 하지 못합니다.
   그 일을 대신 해 주는 것이 바로 Hermes 같은 **에이전트 프로그램**입니다.

## 6. 토큰과 컨텍스트 윈도우

LLM은 글을 낱말보다 조금 작은 조각인 **토큰(token)** ([용어사전](../dict/01_llm_basics.md#token))
단위로 읽습니다("안녕하세요"가 2~3토큰). 그리고 한 번에 읽을 수 있는 토큰 수에
상한이 있는데, 이를 **컨텍스트 윈도우** ([용어사전](../dict/01_llm_basics.md#context-window))라고
합니다. 책상의 크기라고 생각하면 됩니다 — 책상보다 큰 서류 더미는 올려놓을 수
없으니, 대화가 길어지면 오래된 내용을 요약해 치우는
**컨텍스트 압축** ([용어사전](../dict/04_prompt_context.md#context-compression))이 필요해집니다
(→ [07_prompt_context.md](07_prompt_context.md)).

## 7. 프롬프트 — LLM에게 건네는 지시문

**프롬프트(prompt)** ([용어사전](../dict/01_llm_basics.md#prompt))는 LLM에게 주는 입력
글 전체입니다. 그중 **시스템 프롬프트** ([용어사전](../dict/01_llm_basics.md#system-prompt))는
"너는 이런 역할이고 이런 규칙을 지켜라"라고 대화 맨 앞에 놓는 지시문입니다.
연극으로 치면 배우(LLM)에게 주는 **배역 설명서**입니다.

LLM 서버는 "지난번과 똑같은 앞부분"을 다시 읽을 때 요금을 크게 깎아 주는데
(**프롬프트 캐싱**), 그래서 Hermes는 시스템 프롬프트를 대화 도중에 절대 바꾸지
않는 것을 철칙으로 삼습니다. 이 한 가지 원칙이 코드 곳곳의 설계를 결정합니다.

## 8. 에이전트 — 말만 하는 AI에서 행동하는 AI로

**에이전트(agent)** ([용어사전](../dict/02_agent_core.md#agent))는 LLM에게 손발을
붙인 프로그램입니다. 동작 원리는 의외로 단순한 반복문입니다:

```
1. LLM에게 상황을 알려주고 "다음에 뭘 할까?" 묻는다
2. LLM이 "terminal 도구로 ls를 실행해줘" 같은 JSON을 답한다
3. 프로그램이 실제로 그 도구를 실행하고, 결과를 LLM에게 보여준다
4. 할 일이 남았으면 1로 돌아간다 (다 끝났으면 사용자에게 최종 답을 보낸다)
```

이 반복을 **도구 호출 루프** ([용어사전](../dict/02_agent_core.md#tool-calling-loop))라고
하며, Hermes의 심장인 `run_conversation` 함수가 바로 이 루프입니다
(→ [04_agent_loop.md](04_agent_loop.md)). 심부름을 시키면, 비서(에이전트)가
사장님(LLM)의 지시를 받아 전화(도구)를 걸고 결과를 보고하고 다음 지시를 받는
모습을 상상하면 됩니다.

## 9. 데이터베이스 — 기억을 저장하는 서랍장

프로그램을 껐다 켜면 변수에 있던 내용은 사라집니다. 대화 기록처럼 **남겨야 하는
데이터**는 디스크에 저장해야 하고, 이를 체계적으로 해 주는 것이
**데이터베이스(DB)** 입니다. Hermes는 서버 설치가 필요 없는 파일 기반 DB인
**SQLite** ([용어사전](../dict/06_state_retrieval.md#sqlite))를 씁니다. 표(테이블)
형태로 데이터를 넣고, **SQL**이라는 질의 언어로 꺼냅니다. 여기에 전문 검색
기능(**FTS5** ([용어사전](../dict/06_state_retrieval.md#fts5)))까지 얹어 "예전에 그
얘기 뭐였지?"를 찾을 수 있게 합니다 (→ [06_state.md](06_state.md)).

## 10. Git과 저장소(repository)

**Git**은 소스코드의 변경 이력을 기록하는 도구이고, **저장소(repository, 줄여서
repo)** 는 Git으로 관리되는 프로젝트 폴더입니다. "hermes-agent-gyu100 저장소"란
GitHub에 올라가 있는 이 프로젝트 전체를 뜻합니다. 학습자료 속
[`run_agent.py 400-406행`](../run_agent.py#L400-L406) 같은 링크는 저장소 안 실제
파일의 해당 줄로 이동합니다.
