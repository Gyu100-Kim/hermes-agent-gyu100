## 1. 개념

- **Mixture-of-Agents (MoA)**: 여러 개의 LLM(서로 다른 제공자/모델일 수 있음)에게
  같은 질문을 주고, 그 답들을 다시 종합(aggregate)해 최종 답을 만드는 방식.
- 흔한 구조: 여러 "제안자(proposer)" 모델이 각자 초안을 내고, "종합자(aggregator)"
  모델이 그것들을 읽고 하나의 개선된 답으로 합칩니다. 여러 층으로 반복하기도 합니다.
- 핵심 직관: **서로 다른 모델의 강점이 상호 보완**되고, 여러 관점을 종합하면 단일
  모델보다 나은 답이 나올 수 있다.

## 2. 히스토리

- 앙상블(ensemble)은 고전적 머신러닝의 오랜 아이디어입니다(여러 모델의 다수결/평균).
- 이를 LLM 텍스트 생성에 맞게 재해석한 것이 MoA로, 2024년경 "여러 오픈 모델을
  계층적으로 종합하면 단일 대형 모델에 필적/능가할 수 있다"는 연구들이 주목받았습니다.
- **Mixture-of-Experts(MoE)** 와는 다릅니다: MoE는 하나의 모델 내부에서 일부
  파라미터(전문가)만 활성화하는 아키텍처, MoA는 **완성된 여러 모델을 바깥에서
  조합**하는 추론 시점 기법입니다.

## 3. 동향과 주요 결과

- 여러 벤치마크에서 MoA 구성이 단일 모델 대비 향상을 보였다는 보고가 있으나, 대가로
  **여러 번의 API 호출**로 비용·지연이 늘어납니다.
- 그래서 실무에서는 "항상 켜기"보다 **사용자가 특정 질문에 명시적으로 요청**하는
  형태(예: 특정 명령/모드)로 제공하는 경우가 많습니다.

- Hermes는 `/moa <prompt>`로 MoA를 명시적으로 호출합니다. 대화 루프의 진입부에서
  MoA 설정을 분리합니다.

  (`run_conversation`이 `moa_config`를 받고, `decode_moa_turn`으로 사용자 메시지에서
  MoA 설정을 디코드.)
- **설정 CLI**: `hermes moa`(list/configure/delete)로 MoA에 쓸 provider/model 슬롯을
  구성합니다.
  <ref_snippet file="/home/ubuntu/repos/hermes-agent-gyu100/hermes_cli/main.py" lines="14403-14416" />
- 실제 MoA 실행 로직은 `agent/moa_loop.py`, 설정 인코딩/디코딩은
  `hermes_cli/moa_config.py`에 있습니다.
- **왜 명시적 호출인가 (설계 트레이드오프):** MoA는 여러 모델을 부르므로 비용이
  큽니다. 그래서 기본 경로가 아니라 사용자가 `/moa`로 명시할 때만 켜지는, "필요할 때
  쓰는 고급 기능"으로 배치되어 있습니다. 이는 [05](../05_tools.md)의 좁은 허리 철학과
  일관됩니다.
