## 1. 개념

- **자기개선 에이전트(self-improving agent)**: 작업을 수행하며 얻은 경험을 **재사용
  가능한 지식(스킬/메모리)** 으로 축적하고, 그 지식을 다음 작업에 활용해 시간이
  지날수록 더 잘하게 되는 에이전트.
- 두 축이 있습니다.
  - **스킬 축(절차적)**: "어떻게 하는가"를 문서/코드로 저장 → 재사용.
  - **메모리 축(사실/취향)**: "사용자/환경에 대한 사실"을 저장 → 개인화.
- 모델 가중치를 바꾸는 파인튜닝과 달리, 대부분 **프롬프트/외부 저장소** 수준에서
  이뤄지므로 값싸고 즉시 적용됩니다.

## 2. 히스토리

- 초기 에이전트는 매 세션이 백지 상태(stateless)라, 같은 실수를 반복했습니다.
- "경험을 스킬 라이브러리로 축적"하는 접근(예: Voyager 계열의 skill library
  아이디어)이 등장하며, 성공한 행동 시퀀스를 재사용 가능한 단위로 저장하는 방식이
  주목받았습니다.
- 동시에 **장기 기억(long-term memory)** 연구가 발전하며, 대화에서 사실을 추출·요약해
  다음 세션에 주입하는 메모리 시스템들이 나왔습니다.

## 3. 동향과 주요 결과

- **스킬 라이브러리 + 점진적 공개**: 스킬이 많아질수록 전부를 컨텍스트에 넣을 수
  없으므로, "색인만 항상 보이고 본문은 필요할 때 로드"하는 progressive disclosure가
  사실상 표준이 되었습니다.
- **자동 큐레이션**: 축적된 지식이 낡거나 중복되는 문제를 백그라운드 정비로 관리하는
  방향.
- **평가의 어려움**: "장기적으로 더 나아졌는가"는 측정이 까다로워, 벤치마크보다
  실사용 궤적 분석에 의존하는 경우가 많습니다.

## 4. 이 저장소에서의 구현 연결

[09_self_improvement.md](../09_self_improvement.md)가 코드를 상세히 다룹니다. 요약:

- **스킬(SKILL.md)**: 절차적 지식을 마크다운으로 저장. frontmatter의 60자 설명만
  시스템 프롬프트에 색인되고 본문은 `skill_view`로 지연 로드 → progressive disclosure.
  실물 예: [`skills/creative/ascii-art/SKILL.md`](../../skills/creative/ascii-art/SKILL.md)
- **`/learn`**: `agent/learn_prompt.py`가 경험/문서/코드를 스킬로 정제하는 프롬프트를
  만듭니다. 새 코어 도구 없이 기존 도구로 수행(18-22행) — 자기개선을 "가장자리"에서
  구현.
- **큐레이터**: `agent/curator.py`가 유휴 시 포크된 에이전트로 스킬을 정비하되,
  **에이전트 생성 스킬만, 삭제 없이 보관만, 메인 프롬프트 캐시 불침해**의 불변식을
  지킵니다(15-19행).
- **메모리**: `agent/memory_manager.py`가 `MEMORY.md`/`USER.md` 및 외부 provider를
  오케스트레이션(사실/취향 축).
- **가시화**: `agent/learning_graph.py`가 배운 스킬·기억을 그래프로 보여줍니다.
