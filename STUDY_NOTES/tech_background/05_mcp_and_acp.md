# 배경기술 05. MCP와 ACP — 에이전트 상호운용 프로토콜

## 이 문서에서 다루는 큰 맥락

에이전트가 **외부 도구/데이터**와 연결되는 방식(MCP)과, 에이전트가 **클라이언트(에디터

같은 철학을 갖습니다.

## 1. MCP: 개념과 배경

- **MCP(Model Context Protocol)**: LLM 애플리케이션이 외부 "도구/리소스 서버"에
  표준 방식으로 연결하기 위한 프로토콜. 2024년 말 공개되어 빠르게 확산됐습니다.
- 동기: 예전에는 도구마다 통합 코드를 새로 짜야 했습니다(N×M 문제). MCP는 "서버가
  자기 도구를 표준 형식으로 광고하면, 어떤 MCP 클라이언트든 그걸 발견해 쓸 수 있게"
  해서 통합 비용을 낮춥니다.
- 전송 방식: stdio(로컬 프로세스), HTTP/StreamableHTTP, SSE 등.

## 2. ACP: 개념과 배경

- **ACP(Agent Client Protocol)**: 코드 에디터 같은 **클라이언트**가 에이전트와
  통신하기 위한 프로토콜. "에이전트를 어떤 UI에서든 꽂아 쓸 수 있게" 하는 표준.
- MCP가 "에이전트 ↔ 도구"라면, ACP는 "클라이언트 ↔ 에이전트" 방향입니다. 둘은
  보완적입니다.
- JSON-RPC 기반이며, 보통 stdout을 프로토콜 통로로 씁니다.

## 3. 동향과 주요 결과

- MCP는 사실상 "에이전트 도구 통합의 공용 어댑터"로 자리잡아, 수많은 서버(파일시스템,
  GitHub, DB 등)가 공개됐습니다.
- 트레이드오프: 표준화로 통합은 쉬워졌지만, 신뢰할 수 없는 MCP 서버가 악의적 도구를
  광고할 수 있어 **보안 경계**가 중요해졌습니다.
- ACP는 에디터-에이전트 생태계에서 채택이 늘고 있으며, 여러 에이전트를 같은 에디터
  UI에서 교체 사용하는 흐름을 가능케 합니다.

## 4. 이 저장소에서의 구현 연결

- **MCP 클라이언트**: `tools/mcp_tool.py`가 외부 MCP 서버에 stdio/HTTP/SSE로
  접속해 도구를 발견하고, **Hermes 도구 레지스트리에 등록**해 내장 도구처럼 부르게
  합니다.
  <ref_snippet file="/home/ubuntu/repos/hermes-agent-gyu100/tools/mcp_tool.py" lines="2-11" />
  - 설정은 `~/.hermes/config.yaml`의 `mcp_servers` 키(9행). `mcp` 패키지는 **선택
    의존성**이라 없으면 no-op(10-11행) — [02](../02_modules_and_stack.md)의 지연
    의존성 철학과 일치.
  - keepalive/유휴 재활용/병렬 호출 허용 등 실운영 옵션이 config로 노출됩니다(22-35행).
  - MCP가 [05](../05_tools.md)의 Footprint Ladder에서 **마지막에서 두 번째 rung**인
    이유: 강력하지만 매 호출 스키마 비용과 외부 신뢰 문제가 있어 신중히 씁니다.
- **ACP 서버(어댑터)**: `acp_adapter/`가 Hermes를 ACP 에이전트로 노출합니다.
  진입점 `acp_adapter/entry.py`는 stdout을 JSON-RPC 통로로 예약하고 로깅은 stderr로
  분리합니다([10](../10_subsystems.md) 3절). 실행: `hermes-acp` / `hermes acp`.
